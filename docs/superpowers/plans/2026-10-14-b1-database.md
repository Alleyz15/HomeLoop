# HomeLoop B1 Database Implementation Plan

**Scope:** Task_track section 2, B1 only. No B2+ API behavior or frontend work.

## 1. Preserve migration history and establish security primitives

- Confirm the three existing migrations are applied remotely and leave them unchanged.
- Create the first new migration for `profiles.role`, immutable owner/admin roles, `private.is_admin()`, and admin profile visibility.
- Use least-privilege grants and indexed RLS predicates.

## 2. Add reference catalog structures

- Create a migration for `road_catalog`, `pg_trgm`, refresh authorization, `sdp_launches`, and `backtest_ratios`.
- Normalize roads and calculate deterministic modes/counts from non-primary transactions.
- Grant public read access to reference data and full service-role access.

## 3. Add B1 workflow tables

- Create a migration for valuation-request additions, `applications`, `application_events`, `monthly_limits`, and `monthly_limit_usage`.
- Add constraints, foreign-key/RLS indexes, updated-at handling, seeded limits, owner policies, and admin policies.
- Keep owner application updates/deletes unavailable until B4 server functions.

## 4. Add private photo storage

- Create a private `photos` bucket.
- Add owner-prefix insert/select/delete policies and admin read policy.
- Do not permit owner updates or cross-user access.

## 5. Extend local tools with TDD

- Add failing importer tests for the two files and `--only`, then implement them.
- Add failing demo-user tests for create/skip/admin-role behavior, then implement the script without executing it.
- Never expose credentials or print secrets.

## 6. Document and validate

- Update README for B1 tables, targeted imports, and demo-user setup.
- Run Python tests and migration/static checks.
- Run `npx supabase db push --dry-run`, show its complete output, and stop for `确认 push`.

## 7. After confirmation

- Push migrations.
- Run the requested read-only RLS, policy, catalog, owner, and admin simulations in rollback-only transactions.
- Run Supabase security/performance advisors and address B1 findings with new migrations only.
- Update Task_track with date and final commit hash, show `git status`, commit with the required message, and push the current branch.

## Known acceptance-data mismatch

The remote data currently contains 13 rows after the required road normalization for `JLN BIRAI U8/69` and `2 - 2 1/2 Storey Terraced`: 12 exact road strings plus one leading-space variant. The catalog will not silently discard the extra valid transaction; verification will report the resulting count unless the source data or acceptance expectation is corrected.
