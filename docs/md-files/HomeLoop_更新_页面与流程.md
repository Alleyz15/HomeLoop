## 2. 为什么需要 HomeLoop：现在的换屋流程 vs HomeLoop

### 2.1 现在：想换到 SDP 新屋的人要怎么做

```
① 去 sales gallery，问 salesman，看中一个单位
        ↓
② 付订金、签新屋买卖合约（签约时要付 10%）
        ↓
③ 自己去找地产代理卖旧屋
   ・不知道旧屋到底值多少，每个代理说的价格不一样
   ・代理费、律师费、RPGT 加起来要付多少，要自己算
        ↓
④ 挂牌、带人看屋、讲价，要等多久没人知道（通常 3–9 个月）
        ↓
⑤ 担心：旧屋卖不掉或只能贱卖，新屋的分期付款怎么办？
```

**问题：**
- **要找很多方：** salesman、地产代理、律师、银行，各管一段，没有人看整个流程。
- **价格不透明：** 旧屋值多少，只能听代理怎么说。
- **时间不确定：** 旧屋什么时候卖得掉、能卖多少，都没有保证。
- **费用看不清楚：** 订金、律师费、印花税、代理费、RPGT，要自己一项一项去问。
- **进度看不到：** 卖到哪一步了，只能一直打电话问。

### 2.2 用 HomeLoop：同一个网站完成

```
① 网站估价旧屋：给出区间，附 10 笔真实成交作为依据
        ↓
② 在网站上选 SDP 新屋，马上看到「新屋价格 − 旧屋估价」的差额
        ↓
③ 比较两个方案：直接收购，或有保底价、自己拿市场价
   每一项费用都列出来
        ↓
④ 网上提交申请，Dashboard 随时看到进度
        ↓
⑤ 收到最终报价，接受后就能签新屋，不用先卖旧屋
```

### 2.3 对比

| | 现在的做法 | HomeLoop |
|---|---|---|
| 要联络几方 | salesman、代理、律师、银行，各自分开 | 一个网站；SDP 换屋团队负责协调 |
| 旧屋值多少 | 听代理说，每个人说法不同 | 估价区间加 10 笔真实成交，自己看得到依据 |
| 要不要先卖旧屋 | 通常要，或自己承担风险 | 不用，方案 A 直接收购，方案 B 有保底价 |
| 卖不掉怎么办 | 自己承担 | 方案 B：SDP 按保底价买下 |
| 费用 | 自己去问、自己算 | 每一项列在网站上 |
| 进度 | 打电话问 | Dashboard 显示申请状态 |

**一句话：** 现在换屋要跑好几个地方、价格和时间都不透明；HomeLoop 把估价、选新屋、卖旧屋整合成一个透明的线上流程。

## 3. 整体流程

### 3.1 屋主

```
Welcome Page
    │
    ▼
Login / Register
    │
    ▼
Home（/home，2026-10-16 用户批准的登录后主入口）
 ・Your Records → Manage Dashboard → 多笔记录表；展开某份申请看该申请的进度
 ・Your Next Step → Start Free Valuation → 第 ① 步
 ・Room For What's Next → 新 SDP 项目浏览入口（目录画面完成前注明暂不可用）
    │
    ▼
① 估价输入 → ② 估价结果 → ③ 选新屋 → ④ 选方案
    → ⑤ 换屋计划书 + 提交申请（同一页：上半部计划书，下半部填门牌 + PDPA 同意）
    │
    ▼
申请进入 admin 面板
    │
    ▼
收到「初步报价区间」→ 按「我有兴趣，继续」或「不用了」
    │
    ▼
有人上门（方案 B：看屋；方案 A：注册估价师）
    │
    ▼
收到「正式报价」（有效 14 天）→ 接受 / 换方案 / 拒绝 / 要求复核（一次）
    │
    ▼
接受 → 下一步：通过 HIMS 签新屋 e-SPA（方案 B 另外由合作代理联络挂牌）
```

### 3.2 Admin（SDP 换屋团队）：先过滤，再花钱

```
屋主提交申请
      ↓
【第 1 关：系统自动检查】不花钱
  不合格 → 根本不能提交
      ↓ 合格的才进 admin 面板
【第 2 关：Admin 书面初审】不花钱
  看资料齐不齐、照片、旧屋贷款余额、新屋户型还有没有、是否重复申请
  → 发「初步报价区间」（按 AI 估价算）
  → 屋主按「我有兴趣，继续」才进下一关
      ↓
【第 3 关：上门】开始花钱
  方案 B：SDP 员工或合作代理看屋（成本低）
  方案 A：注册估价师正式估价（约 RM1,600）
      ↓
【第 4 关：正式报价】
  admin 填看屋结果 → 系统按公式算 → admin 批准 → 屋主决定
```

**为什么先发初步报价区间：** 屋主在有人上门前就知道大概能拿多少，觉得太低可以直接停；SDP 只为表态「继续」的申请花钱请人上门，估价费不会浪费；屋主看到的数字一路一致（AI 区间 → 初步报价区间 → 正式报价）。

### 3.3 申请状态（屋主和 admin 看到同一套）

| 状态 | 意思 | 谁推进 |
|---|---|---|
| `submitted` | 已提交，等待初审 | 屋主 |
| `under_review` | Admin 书面初审中 | admin |
| `info_requested` | Admin 要求补充资料 | admin → 屋主补交后回到 `under_review` |
| `indicative_sent` | 已发初步报价区间，等屋主回复 | admin |
| `owner_proceed` | 屋主同意继续 | 屋主 |
| `inspection_scheduled` | 已安排看屋或估价师上门 | admin |
| `inspected` | 已上门，等待出正式报价 | admin |
| `offer_sent` | 已发正式报价（14 天内有效） | admin |
| `review_requested` | 屋主要求复核（只能一次） | 屋主 → admin 处理后回到 `offer_sent` |
| `accepted` / `declined` / `expired` / `rejected` / `withdrawn` | 接受、拒绝报价、过期、admin 拒绝、屋主在初步报价阶段不继续 | 各方 |

**接受报价之后的追踪状态**（让屋主有完整的体验；HomeLoop 无法直接连接 HIMS 或银行，所以由屋主或 admin 手动更新）：

| 状态 | 意思 | 谁更新 |
|---|---|---|
| `espa_signed` | 新屋 e-SPA 已在 HIMS 签署，已付 10% 订金（方案 A 为订金互抵） | 屋主按「我已签约」，admin 确认 |
| `listed` | 方案 B：旧屋已由合作代理挂牌 | admin |
| `buyer_found` | 方案 B：找到买家，已签旧屋 SPA | admin |
| `guarantee_triggered` | 方案 B：期限到了还没卖出，SDP 按保底价买下 | admin |
| `old_home_completed` | 旧屋交易完成，屋主已收到款项 | admin |
| `handover` | 新屋交屋 | admin |

## 4. 估价输入的设计（第 ① 页）

**全部资料都来自 NAPIC 真实成交数据。** 数据有路名（100% 有，约 3.3 万条路，94% 的路只对应一个期数），没有门牌、没有发展商、基本没有 phase。

| 步骤 | 用户做什么 | 系统自动做什么 |
|---|---|---|
| 1. 路名 | 输入并搜索路名（JLN / JALAN 视为同一个词） | 带出期数、县，以及是否 SDP township |
| 2. 屋型 | 从这条路真实成交过的屋型里选 | 只列出存在的屋型 |
| 3. 单位类型 | 选「中间单位」、「角头/尾端」或「自己输入」 | 「中间单位」自动带入这条路最常见的地段与建筑面积（同一条路、同屋型平均 75% 的房子面积相同） |
| 4. 地契 | 确认 | 按数据自动带入永久或租赁 |
| 5. 照片（可选） | 上传 | 没上传就显示该屋型的示意图，标明「示意图」 |

- 找不到路名时：改用 township 或期数名称搜索。
- 面积可以切换 m² 和 sq ft；排屋提供快捷按钮（20×70 尺、22×75 尺、22×80 尺）。
- 不问门牌号码、发展商、phase。

**例子：** `JLN BIRAI U8/69`（Bukit Jelutong）有 12 笔成交，其中 7 笔是地段 178 m²、建筑 190 m²（中间单位），其余 5 笔地段 290–441 m²（角头或尾端）。

### 5.3 第 ③ ④ ⑤ 步的细节（2026-10-14 讨论后确定）

**第 ③ 步：选新屋**
```
在售项目列表（卡片）
   ↓ 点进去
项目详情：选户型
   价格 = 官网起价（多数项目只公布起价）
        或用户填的销售报价（选填，有填就用）
   ↓ 「选这个」
第 ④ 步
```

**第 ④ 步：选方案**
```
方案 A 卡片 ｜ 方案 B 卡片（只显示：拿到多少、多快、适合谁）
引导问题：「签新屋时，你能先付约 10% 的订金吗？」
   可以 → 推荐方案 B；不行 → 推荐方案 A
   ↓ 点其中一个
该方案的详细计算（每一项扣除都列出来）
   ↓ 「确认这个方案」
第 ⑤ 步
```

两个方案的定位（更正后）：

| | 方案 A：直接收购 | 方案 B：保底价 |
|---|---|---|
| 一句话 | 价格今天就确定，不用等买家，订金直接用旧屋抵 | 拿接近市价的钱，还有保底价 |
| 价格什么时候确定 | 第一天 | 找到买家时（只保证最低价） |
| 要不要等买家 | 不用 | 要，0–9 个月（模拟假设） |
| 多久拿到钱 | 约 1–3 个月（**假设**：SDP 用现金，但过户手续照样要走） | 约 3–13 个月（找买家 + 签约后 3–4 个月完成交易） |
| 订金缺口 | 几乎没有（订金互抵，见下） | 有，要自己先付约 10% |
| 拿到多少 | 约市价 79% | 约市价 96% |
| 适合谁 | 手上没有现金付订金、不想等、怕麻烦 | 手上有现金先付订金、愿意等几个月 |

**方案 A 的订金互抵（设计假设）：** SDP 同时是旧屋的买方和新屋的卖方，两份合约同一天签，SDP 要付的旧屋订金直接抵屋主要付的新屋订金，屋主不用先拿出 10%。交易完成时由 SDP 一方的银行赎回旧屋贷款（槟城换屋计划和英国 part exchange 都是类似做法）。合约在 HDA 法定格式下怎么写，交给律师处理。

**第 ⑤ 步：换屋计划书**

目的：第 ④ 步回答「我拿到多少钱」，第 ⑤ 步回答「接下来会发生什么、什么时候要付钱」。

页面三个区块：
1. **时间线**（按选的方案显示，见 5.4）
2. **钱什么时候出、什么时候进**（每项标「约」）
3. **要准备的东西**：旧屋地契或买卖合约、旧屋贷款余额、身份证（签 e-SPA 时用 iDsaya 认证）、新屋贷款预先批核

同一页下半部：填完整地址（门牌自动接上路名）、地契号码（可选）、PDPA 同意勾选 →「提交换屋申请」。（第 ⑤⑥ 步已确定合并）

### 5.4 时间线的依据（已查证）

| 步骤 | 需要多久 | 依据 |
|---|---|---|
| 新屋：签 SPA 时才付 10% | 发展商依法**不能**收订房费 | HDA 条例 11(2) |
| 新屋：签 e-SPA | 2026/1/1 起必须通过 KPKT 的 HIMS，用 iDsaya 认证 | KPKT |
| 新屋：交屋 | 签约后 24 或 36 个月 | HDA 法定合约 |
| 旧屋：找到买家后签 SPA | 约 14 个工作天内，买家付到 10% | 二手交易标准做法 |
| 旧屋：完成交易、卖方拿到钱 | 签约后 **3 个月**，可延 **1 个月**（买家付迟付利息，一般约年息 8%） | 二手交易标准做法 |
| 旧屋：租赁地契州政府同意 | 另加 **1–3 个月**，3 个月从拿到同意后才开始算 | 二手交易标准做法 |
| 旧屋：RPGT | 买家扣留售价 **3%** 交税务局；卖方 60 天内申报、90 天内缴税；持有满 5 年税率 0%，扣留款可申请退回 | 税务局规定 |
| 看屋或估价师上门、发出报价 | 约 1–2 周 | **假设**，没有官方标准 |
| 方案 B 找买家 | 0–9 个月 | **模拟假设**（3 / 6 / 9 个月三种情境） |

**方案 B 时间线（永久地契）：**
```
第 0 天          提交申请
约 1–2 周        看屋，确认保底价，收到报价
接受报价后       通过 HIMS 签新屋 e-SPA，付 10% 订金          ← 钱出去
第 0–9 个月      代理挂牌找买家（期限到了还没卖 → SDP 用保底价买下）
找到买家         约 14 个工作天内签旧屋 SPA
签约后 3–4 个月  完成交易，拿到钱（扣 3% RPGT 扣留款和旧屋贷款余额）← 钱进来
（租赁地契再加 1–3 个月）
约 24–36 个月    新屋交屋
```

**方案 A 时间线：**
```
第 0 天          提交申请
约 1–2 周        注册估价师上门，正式估价，收到收购报价
接受报价后       同一天签：SDP 买旧屋的合约 + 新屋 e-SPA（订金互抵）
约 1–3 个月      完成旧屋交易，SDP 付款（扣 3% RPGT 扣留款和旧屋贷款余额）（假设）
约 24–36 个月    新屋交屋
```

**订金缺口提醒（方案 B）：** 「签约时要先付约 10% 订金，旧屋的钱最快约 3–4 个月、最慢可能超过 1 年才到。」用户输入的是租赁地契时，时间线自动加上「州政府同意 1–3 个月」。

### 5.5 决定规则：Admin 批不批、屋主接不接受

**第 1 关：系统自动检查（不合格不能提交）**

| 规则 | 不合格时 |
|---|---|
| 新屋是 SDP 在售项目 | 不能提交 |
| 旧屋在 7 个县内 | 不能提交 |
| 方案 A：旧屋在 SDP township | 方案 A 不能选 |
| 方案 A：旧屋估价不高于新屋价格 | 方案 A 不能选 |
| 期数近 3 年成交足够 | 可以提交，但标「需人工估价」 |

**第 2 关：Admin 书面初审（不花钱）**
- 检查：资料是否齐全、照片、旧屋贷款余额、新屋户型是否还有、是否重复申请。
- 按钮：**发初步报价区间** / **要求补充资料** / **拒绝**（从清单选原因）。
- 初步报价区间按 AI 估价区间计算：方案 A =（AI 低价 ~ AI 高价）×（1 − 11.5% − 10%）；方案 B 保底 = AI 中间值 × 75%，并显示预计可拿到的市价范围。

**第 3 关：上门后 Admin 填的三样东西**

| 填什么 | 选项 |
|---|---|
| 单位类型确认 | 与用户填的相同 / 不同（例如其实是角头单位） |
| 屋况 | 良好 / 一般 / 需要维修 |
| 确认后的市价 | 方案 A：注册估价师的正式估价；方案 B：默认 AI 估价，看屋后可调整，**必须写原因** |

**第 4 关：正式报价（系统按公式算，admin 按按钮）**

| | 公式 |
|---|---|
| 方案 A | 收购价 = 正式估价 ×（1 − 成本 11.5% − 缓冲 10%） |
| 方案 B | 保底价 = 确认后的市价 × 75% |

- 按钮：**批准并发出报价** / **要求补充资料** / **拒绝**（从清单选原因：结构问题、产权问题、超出每月额度等；屋主看得到原因）。

**系统自动标记（显示在列表上）**
- 正式估价比 AI 区间最低价还低 10% 以上（可能有屋况问题）。
- AI 可信度「低」。
- 本月保底或收购额度快用完。

**屋主收到正式报价后（有效 14 天）**

| 屋主可以 | 结果 |
|---|---|
| ✅ 接受 | 显示下一步：通过 HIMS 签新屋 e-SPA；方案 B 加「合作代理会在 3 天内联络你挂牌」 |
| 🔄 换另一个方案 | 用同一份看屋结果重新算另一个方案的报价，不用再上门（方案 B 换 A 时，仍需注册估价师正式估价） |
| ❌ 拒绝 | 申请关闭，估价记录保留，之后可以重新申请 |
| 💬 要求复核（只能一次） | 写原因并可附照片，admin 重新看一次后再发报价 |

- **不做议价**：价格按公式和看屋结果决定，保持透明。
- 报价过期要重新申请，因为房价会变。

### 5.6 Dashboard 的设计

**原则（2026-10-16 用户批准更新）：Home 提供入口，Dashboard 管理多笔记录；进度条属于某份申请，不属于整个账号。**

- Dashboard 顶部显示总记录、进行中申请、待屋主处理、已交屋的汇总；待处理申请也计入进行中，不把两者相加。
- 表格列出申请与未关联申请的已保存估价；显示旧屋、新 SDP 项目、方案、状态、更新日期及操作。每页 10 笔，可搜索和按状态筛选；手机改为记录卡。
- 展开一份申请后，在该行下方显示它自己的 Connected Journey、旧屋/新屋/方案及当前状态。单纯估价没有申请进度条，只能查看估价结果。
- 不新增草稿或未完成表单恢复。允许保存多笔估价；后端仍限制每位屋主同一时间只有一份活跃的已提交申请。关闭/拒绝/撤回等历史申请保留，完成换屋以 handover 为准。
- 暂无真实数据支撑的将来日期、保证期截止和结算净额，不虚构。完整报价回应及后续流程画面仍按各自阶段实施。

**进度条（共 8 格，按方案显示）：**
```
估价 → 提交申请 → 初步报价 → 上门 → 正式报价 → 签新屋合约 → 旧屋交易完成 → 新屋交屋
```
- 方案 B 在「签新屋合约」和「旧屋交易完成」之间多显示一个子进度：挂牌中 → 找到买家（或保底触发）。
- 每一格显示日期（已完成）或预计时间（未完成，按 5.4 的时间线估算）。

**简略卡片（显示在进度条下面）：**

| 当前状态 | 卡片内容 | 按钮 |
|---|---|---|
| 新用户 | 「免费估价你现在的房子」 | 开始估价 |

实现路由（2026-10-20）：在 `/dashboard` 展开本人的申请后，点「Open application details & respond」进入 `/dashboard/applications/[id]`。这是 Dashboard 下的个别申请子视图，不是重新填写第 ⑤ 步。按实际阶段显示回应表单；补件与正式报价复核可附最多 5 张 JPEG / PNG / WebP 照片，每张最多 5 MiB（显示为 5 MB），只给本人及授权团队查看。内部 audit note / payload 不显示给屋主。照片/讯息扩展必须先部署前一阶段 backend migration；未部署时不伪造记录或成功回应。
